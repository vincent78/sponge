## 快速摘要

### 架构总览（模块与依赖）

本篇是文档库的索引，不引入新的运行时模块。它把仓库目录映射到 01–17，标明覆盖状态、测试缺口和待确认项。阅读其它篇章时若不知道该打开哪份文件，以本篇矩阵为准。

文档分层没有跳级：01 骨架 → 02 全路径例子 → 03 主链路拆解 → 04–17 按模块补齐。代表性功能是 `sponge web http` 生成 HTTP CRUD，再 `GET /api/v1/<table>/{id}`。

### 核心调用序列（逐步逻辑）

本篇没有独立运行调用。它的消费顺序是：

1. 写文档前用 `git rev-parse HEAD` 固定基准提交 `23807238c62e0f3b3e2d9a341bbef50547d3f5ec`。
2. 按「入口 → 测试 → 单功能调用链 → 扩展覆盖」阅读源码。
3. 将每个顶层目录登记到下表「计划文档」列。
4. 第四层写完后回填覆盖状态、缺口与推断项。

### 易错点与边界条件

- 「已覆盖」指文档追踪到真实符号与调用关系，不是「提到目录名」。
- `third_party/`、生成的 `*.pb.go` 只说明契约与生成方式，不逐行转录。
- 本次任务 **未运行** 测试套件与 `make run`；测试结论来自阅读测试代码。
- 工作区 dirty：不要把未提交的 `go.mod` 等本地改动当成基准提交行为。
- 旧目录 `docs/sourceReader1/`、`docs/sourceReader2/` 是历史笔记，不是本套文档的权威源；行为以源码与本目录为准。
