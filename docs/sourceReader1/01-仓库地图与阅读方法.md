# 01. 仓库地图与阅读方法

## 顶层目录

| 目录 | 身份 | 重点 |
|---|---|---|
| `cmd/sponge` | 生成工具本体 | CLI、UI 服务、生成/合并/修补/性能测试 |
| `cmd/protoc-gen-*` | protoc 插件 | Gin、RPC 模板和 JSON 字段生成 |
| `cmd/serverNameExample_*` | 服务启动模板 | HTTP、gRPC、网关、混合服务的 main/initial |
| `api` | Proto 示例与生成结果 | API 契约、HTTP 映射、校验规则 |
| `internal` | 业务项目模板 | config、server、router、handler/service、dao/cache/model |
| `pkg` | 可复用库 | HTTP/gRPC 基建、数据库、缓存、日志、追踪等 |
| `configs` | 配置与嵌入支持 | 默认 YAML 和定位配置文件的辅助代码 |
| `deployments`、`scripts` | 交付模板 | Docker、Compose、Kubernetes、构建/protoc 脚本 |
| `third_party` | Proto 依赖 | Google API、validate、tagger、OpenAPI 注解 |
| `test` | 仓库级测试素材 | 自动测试、服务测试和 SQL 样本 |
| `docs` | Swagger 生成物/文档 | `docs.go` 等文件多为 swag 生成结果 |

Go 的 `internal` 规则意味着该目录只能被父模块范围内代码导入；`pkg` 则有意允许外部项目使用。

## 识别“源文件”和“生成素材”

文件头出现 `Code generated ... DO NOT EDIT` 时，优先寻找它的来源。例如配置结构由配置生成命令维护，`*.pb.go` 来源是 proto。直接编辑生成结果，下次生成就可能丢失。

仓库中的样板业务并不是一个具体产品。`UserExample` 故意覆盖典型 CRUD 字段，便于生成器从它替换出真实表模型。阅读时把它看作“模板测试夹具”。

## 依赖分层

大致依赖方向如下：

```text
cmd/*（进程入口）
  ↓
internal/*（应用私有层）
  ↓
pkg/*（通用能力）
  ↓
Gin / gRPC / GORM / Redis / OTel 等第三方库
```

业务层内部又是：

```text
router → handler              （HTTP）
grpc registration → service  （gRPC）
handler/service → dao → database
                    ↘ cache
```

模型 `model` 和传输对象 `types`/proto 分开。这样数据库字段变更不会被迫等同于对外 API 变更，二者通过 `pkg/copier` 转换。

## 新手逐文件阅读技巧

1. 先找构造函数：`NewXxx` 通常能看到依赖如何注入。
2. 再找接口断言：`var _ Interface = (*impl)(nil)` 表示编译期确认实现关系。
3. 搜索注册点：HTTP 路由和 gRPC service 都通过包级 `init()` 把函数追加到切片，导入包时自动完成注册。
4. 最后看 Option：大量组件使用 functional options，即 `WithXxx` 函数修改内部 option 结构。
5. 遇到生成代码先回溯 `.proto`、SQL parser 或 `.tpl`，不要只分析结果。

## 建议常用搜索

```bash
rg 'func main\(' cmd
rg 'func New[A-Z]' internal pkg
rg 'registerFns|apiV1RouterFns' internal
rg 'todo generate|delete the templates' -g '*.go' -g '*.proto'
rg 'Code generated' -g '*.go'
```

## 容易误判的地方

- `cmd/sponge/server` 是生成器 UI 的 HTTP 后端；`internal/server` 是被生成业务服务的 transport 层。
- `pkg/cache` 是通用缓存实现；`internal/cache` 是带业务键规则的缓存访问层。
- `pkg/sgorm` 包装数据库基础能力；`internal/dao` 才保存某个实体的查询语义。
- 根仓库为了存放各种模板会同时出现 HTTP 和 gRPC 代码，实际生成的项目会按生成类型选择子集并删除模板标记区。
