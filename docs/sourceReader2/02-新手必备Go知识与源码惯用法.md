# 02. 新手必备 Go 知识与源码惯用法

## 1. 接口与编译期断言

常见写法：

```go
var _ app.IServer = (*httpServer)(nil)
```

它不会创建对象，只要求编译器检查 `*httpServer` 是否实现接口。若少了方法，编译立即失败。接口通常定义在使用者一侧，使 handler/service 可以依赖 DAO 接口而非具体数据库实现。

重实现建议：接口保持小，按调用者需要定义；不要为每个 struct 机械创建巨大接口。

## 2. 构造函数与依赖注入

Go 没有内置 DI 容器。Sponge 通过 `NewXxx` 手工装配：

```text
NewHandler
  → NewDAO(database.GetDB(), NewEntityCache(...))
```

好处是依赖清晰，缺点是模板中的构造可能依赖全局 getter。单测可以通过同包构造或接口替身替换依赖。重写时可让构造函数显式接受 DAO，进一步提升可测性。

## 3. Functional Options

大量包使用：

```go
type Option func(*options)

func WithTimeout(v time.Duration) Option {
    return func(o *options) { o.timeout = v }
}
```

构造时先加载默认值，再依次执行 option。它解决可选参数增多和 API 兼容问题。阅读时总要先找 `defaultOptions`，否则无法知道未传 option 时的真实行为。

## 4. 包级 `init()` 注册

路由和 gRPC service 常这样注册：

```go
func init() {
    registerFns = append(registerFns, func(s *grpc.Server) { ... })
}
```

只要包被导入，Go 会在 main 前执行 init。优点是新增业务文件无需修改中心 switch；缺点是注册是隐式的、顺序受包初始化规则控制、测试隔离困难。

重实现时可先用显式 `RegisterAll`，理解后再决定是否采用 init 插件式注册。

## 5. `context.Context`

context 传递取消信号、deadline 和请求范围值。HTTP handler 通过 wrapper 将 Gin context 中的 request ID/trace 信息放到标准 context，DAO 和外部调用继续接收它。

规则：

- context 通常是函数第一个参数；
- 不把它存进长期 struct；
- 创建 timeout 后调用 cancel；
- 不用 `context.Background()` 覆盖已有请求 context；
- key 使用私有类型避免冲突。

## 6. goroutine、channel 与 errgroup

`app.Run` 用 errgroup 并发启动 server；命令执行器用 channel 流式返回 stdout；UI 用 goroutine 延迟清理临时目录。

阅读并发代码要回答：谁关闭 channel、goroutine 怎样退出、错误如何回传、context 取消后是否仍阻塞。只有启动 goroutine 没有退出协议会泄漏资源。

## 7. `embed.FS`

UI 静态资源和某些模板可通过：

```go
//go:embed static
var staticFS embed.FS
```

编译进二进制。`fs.WalkDir` 可以遍历只读资源。若需要动态修改前端配置，代码会把 embed 内容复制到本地目录后替换；embed 本身不可写。

## 8. `text/template`

`sql2code/parser` 使用 `text/template` 生成 Go、JSON 和 Proto 片段。模板执行输入是 `tmplData`，通过 `{{range .Fields}}` 遍历列。

模板只负责展示，类型决策和字段过滤应在执行前完成。生成 Go 后使用 `go/format.Source`，既格式化又验证语法。

## 9. AST 与文本替换的边界

- SQL AST：把 DDL 解析成表、列、约束，适合结构化理解；
- Go AST：适合修改 import、声明、路由等语法结构；
- 文本替换：适合稳定占位符和模板标记；
- 正则：只适合局部、格式受控的机械修补。

重新实现生成器时优先 AST/结构化数据，文本替换留在最后输出层。用字符串解析任意 Go 源码会非常脆弱。

## 10. `defer` 与资源关闭

数据库 rows、连接、文件和响应体常用 defer 关闭。注意 defer 在当前函数返回时执行；长生命周期函数中 defer 会延迟很久。循环内创建资源时最好提取子函数，避免 defer 堆积。

## 11. 错误包装和判断

代码中既有 `fmt.Errorf("...: %v", err)` 也有可保留链的包装。新实现应优先 `%w`，调用方用 `errors.Is/As` 判断，例如识别 record not found。不要靠字符串 contains 区分可编程错误，除非第三方库没有类型化错误。

## 12. 测试替身

仓库使用 sqlmock、miniredis、httptest、直接 service 调用等。接口替身验证业务交互，sqlmock 验证 SQL，真实集成环境验证 driver 行为。三者目标不同，不能只保留一种。

## 13. 新手常见误区

1. 把所有全局变量当作常量：配置、replacer 注册表和 router slice 都是可变状态；
2. 认为 import 但未调用的包没有作用：可能依赖其 init 注册；
3. 直接编辑 pb.go：重新生成会覆盖；
4. 忽略 option 默认值：实际行为可能与调用处表面不同；
5. 只读成功路径：生成器的文件存在检查、超时和清理才决定可用性；
6. 把 context 当万能参数 map：它只适合请求范围的少量元数据。
