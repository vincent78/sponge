# 07. 数据库到代码的核心算法

本章描述 Sponge 最核心的算法：如何从数据库或 DDL 得到 model、DAO 片段、HTTP DTO、Proto、Service 元数据。主要代码位于 `pkg/sql2code` 和 `pkg/sql2code/parser`。

## 1. 总入口与输入优先级

所有基于表的命令最终调用：

```go
codes, err := sql2code.Generate(&sql2code.Args{...})
```

`Args` 支持三种 schema 来源，优先级为：

```text
SQL 字符串 > DDLFile > DBDsn + DBTable
```

除此之外还控制 driver、package、GORM/JSON tag、JSON 命名、公共 Model 嵌入、nullable 风格、表/列前缀、Web Proto、扩展 API 和自定义模板。

`GenerateOne` 只是调用 `Generate` 后按 `CodeType` 取一个结果；真正算法只有一套。

## 2. 为什么统一成 MySQL 风格 DDL

SQL parser 使用统一 AST。MySQL 可直接 `SHOW CREATE TABLE`，其他数据库先抽取元数据再转换为 parser 能理解的临时 MySQL DDL：

```text
MySQL/TiDB ─ SHOW CREATE TABLE ───────────────┐
PostgreSQL ─ catalog → PGFields → 临时 DDL ──┤
SQLite ───── PRAGMA → SqliteFields → 临时 DDL ┤→ ParseSQL
MongoDB ──── document → MgoFields → 临时 DDL ┘
```

PostgreSQL/MongoDB 同时返回 `fieldTypes map[column]type`，保留临时 DDL 无法表达的真实类型与嵌套结构。

## 3. 各数据库 schema 获取

### MySQL/TiDB

`GetMysqlTableInfo` 用 `database/sql` 打开连接，执行 `SHOW CREATE TABLE`，scan 第二列 DDL。它保留默认值、注释和约束，但只获取指定单表。

### PostgreSQL

`GetPostgresqlTableInfo` 通过 GORM 查询 `pg_class`、`pg_attribute`、`pg_type`、`pg_description` 和 `information_schema` 主键约束，得到列名、原生类型、长度、nullable、注释、主键。

`ConvertToSQLByPgFields` 把 integer/jsonb/boolean 等临时映射为 int/json/bit(1)，同时保存原生类型 map。当前查询没有把 schema 作为独立输入，重实现时应支持 schema 并使用参数化查询。

### SQLite

`GetSqliteTableInfo` 调用 `PRAGMA table_info`，获取 name/type/notnull/default/pk，再进行宽松类型映射。SQLite 类型亲和性和约束比结果丰富，现实现重点是生成 CRUD，而非完整迁移工具。

### MongoDB

`GetMongodbTableInfo` 查询 `_id` 最大的一条 document，按 BSON element 推断类型。嵌套 document 和 array 会递归生成子 struct/Proto message；缺少 created/updated 时间时会补字段；`_id` 暂时转为 `id varchar(24)`，真实 `primitive.ObjectID` 留在 type map。

这是抽样推断而非真正 schema：空集合会失败，稀疏字段可能缺失，混合类型只反映样本。更稳健的重实现应扫描可配置数量的文档，合并字段并报告类型冲突。

## 4. SQL AST 到统一中间模型

`parser.ParseSQL`：

1. 初始化内置 template；
2. 应用 functional options；
3. 解析 SQL 为 statements；
4. 只处理 `*ast.CreateTableStmt`；
5. 每张表调用 `makeCode`；
6. 合并各表的代码片段和 import。

`makeCode` 构造 `tmplData`：表原名、Camel 名、小驼峰名、注释、driver、字段、主键信息和 MongoDB 子结构。

每列变成 `tmplField`：

```text
ColName       数据库原列名
Name          Go 导出字段名
GoType        目标 Go 类型
JSONName      JSON 字段名
Tag           gorm/bson/json tag 内容
Comment       列注释
IsPrimaryKey  是否主键
rewriterField 特殊 model 类型及 import
```

## 5. 命名算法

- 可裁剪 `TablePrefix` 和 `ColumnPrefix`；
- snake_case 转 CamelCase；
- `id`/`user_id` 等有 ID 大写特殊处理；
- JSON 可选 snake_case 或 lowerCamel；
- 使用 inflection 生成复数；
- GORM 默认复数表名与真实表名不一致时生成 `TableName()`。

命名是生成器兼容性的公共协议。重写时应把命名器做成独立、穷举测试的纯函数。

## 6. 类型映射

`mysqlToGoType` 是关系型统一类型入口：整数考虑 unsigned，tinyint(1) 为 bool，字符串/Blob 为 string，时间为 `time.Time`，JSON/decimal/bit 带 rewrite 信息，nullable 可选 `sql.Null*` 或指针。

特殊 rewrite 让同一列在不同层有不同表达：

| 数据库列 | model | HTTP/Service | Proto |
|---|---|---|---|
| JSON | `*datatypes.JSON` | 可转换的普通表示 | string |
| decimal | `*decimal.Decimal` | 适配类型 | string |
| datetime | `*time.Time` | 时间/字符串约定 | string 或时间适配 |
| Mongo `_id` | `primitive.ObjectID` | string | string |

未知类型会变成 `UnknownCustomType`，让生成结果显式暴露需人工处理的字段，而不是悄悄猜错。

## 7. 主键与 CRUD 风格

`newCrudInfo` 依次选择：显式主键、首个 `_id` 列、首个适合的整数/字符串列、第一列兜底。它计算主键的单复数命名、Go/Proto 类型及是否 string。

只有名为 `id` 的常用整数主键属于默认风格；其他主键触发 common style，generator 选择 `.tpl` 并把 `ByID` 等逻辑改为真实主键。

现实现对复合主键只记录第一列。重新实现若要支持复合键，应让 `CrudInfo` 保存 `[]KeyField`，并同步改变 URL、cache key、DAO where 和 Proto request。

## 8. 一次生成的所有输出

`makeCode` 从同一个中间模型产生：

- `model`：完整 package/import/struct、TableName、列白名单；
- `json`：示例 JSON；
- `dao`：部分更新的 map 填充片段；
- `handler`：Create/Update/Detail HTTP DTO；
- `proto`：基础或扩展 RPC、message、可选 HTTP/OpenAPI 注解；
- `service`：service 使用的字段结构片段；
- `crud_info`：主键/命名控制元数据 JSON；
- `table_info`：自定义模板使用的完整表元数据 JSON；
- `__table_name__`：实体名称。

parser 不生成完整 handler/DAO。稳定的控制逻辑来自工程模板，parser 只产生随 schema 变化的部分。

## 9. Model 生成细节

`getModelStructCode` 会：

1. 按 embed 过滤公共 id/time/delete 字段并嵌入 `sgorm.Model`；
2. 修正 ID、时间、JSON、decimal、bool 和 Mongo 类型；
3. 执行 `modelStructTmpl`；
4. 追加 Mongo 子结构；
5. 恢复真实 BSON tag；
6. 生成 `XxxColumnNames` 白名单防动态列名注入；
7. 用 `go/format.Source` 验证并格式化。

## 10. Update 片段的语义限制

模板只在字段非零时加入 update map。这样自然实现 PATCH 风格部分更新，但无法表达“把数字改成 0、bool 改成 false、字符串改为空”。生产级重实现可选择：

- request 字段全部用指针；
- 使用 `map[string]json.RawMessage` 记录存在性；
- 让客户端传显式 update mask；
- 区分 PUT 全量更新与 PATCH 部分更新。

## 11. Proto 生成矩阵

两个 bool 形成四种模板：纯 gRPC/带 HTTP 映射 × 基础 5 API/扩展 9 API。`goTypeToProto` 转类型，随后固定 mark 插入 Create/Update/Detail message，再根据 DB/主键调整 ID 类型和 validate/tagger。

字段编号是协议兼容性的关键。已有 proto 更新时不能因列顺序变化复用旧编号。基于数据库每次重建 proto 的方案更适合初次生成；后续演进应以 proto 为事实来源。

## 12. 自定义模板数据

`IsCustomTemplate` 跳过内置代码，输出结构化 `TableInfo`：表的各种命名、注释、driver、列信息、主键信息和子结构。自定义模板可以消费它生成非 Go 文件。

## 13. 最小重实现伪代码

```go
schema := source.Load(ctx, input)
table := normalize(schema)       // 不同 DB → 统一 Table
validate(table)
names := naming.Build(table)
types := mapper.Map(table)
meta  := crud.Build(table, names, types)

fragments := renderer.Render(meta)
project := assembler.Select(projectOptions)
assembler.Write(project, fragments, output)
verify.GoFmtAndCompile(output)
```

与现源码相比，这个版本直接定义结构化 `Table/Column`，避免 PostgreSQL/MongoDB 先伪装成 MySQL DDL。兼容现有 parser 时可以保留 DDL adapter。

## 14. 必须具备的测试

- 每种数据库的 schema fixture；
- unsigned/nullable/default/comment/unique/时间/JSON/decimal；
- 标准 ID、字符串主键、非 ID 整数主键、无主键、复合主键；
- snake/camel、表列前缀、特殊缩写；
- 基础/扩展、Web/non-Web Proto 组合；
- golden 文件经过 gofmt/protoc；
- 同一输入输出确定性；
- 错误输入不留下半成品目录。
