# 19. 测试、构建、部署与质量验证

## 1. 测试不是一个层次

仓库约有 197 个 Go 测试文件，目标不同：

| 层次 | 常用工具 | 验证内容 |
|---|---|---|
| 纯函数单测 | testing/testify | 命名、类型映射、配置、编码 |
| 文件/golden 测试 | 临时目录、expected text | parser、replacer、AST 修改 |
| 协议测试 | httptest、直接 RPC 调用 | binding、response、错误映射 |
| 数据替身 | sqlmock、miniredis | SQL、cache key/TTL、错误路径 |
| 集成测试 | 真实 DB/Redis/registry/message | driver 和外部系统真实行为 |
| 生成 smoke test | CLI + 临时输出 | 生成项目能 gofmt/build/test |

重新实现不能只运行 `go test ./...` 看绿色；应知道失败属于哪个层次、是否需要外部环境。

## 2. 生成器测试策略

最有效的是 table-driven + golden：每个输入 DDL 和 options 对应期望 model/DTO/proto/metadata。更新 golden 必须人工审查差异，不能无条件覆盖。

replacer 测试需要验证：子目录白名单、ignore、大小写替换、二进制文件、目标已存在、路径分隔符和 embed.FS。

完整生成 smoke test 应在临时目录运行，并检查：无占位符、无模板特殊后缀、go fmt 通过、go list/build 通过、proto 可编译、关键文件存在。

## 3. 服务测试策略

- handler：构造请求，验证参数错误、成功、DAO 错误、not found、响应 code 和 request ID；
- service：验证 Proto Validate、转换错误、DAO 错误到 status code；
- DAO：验证 where、排序白名单、分页、事务、软删除、零值更新；
- cache：命中/未命中、损坏值、TTL、并发、写后失效；
- server/app：启动错误、信号退出、超时 shutdown、注册/注销配对。

## 4. 根 Makefile

主要目标包括 install、lint、test、cover、graph、docs、proto、build、run、镜像、二进制打包、Kubernetes 部署和 patch。生成项目会按 HTTP/gRPC 形态选择不同 Makefile。

把 Makefile 看作“开发流程 API”：README 和 CI 都依赖其目标名。重写时先保留少量稳定目标 `fmt/lint/test/generate/build/run`。

## 5. Proto 工具链

`scripts/protoc.sh` 管理 include path 和插件。输出可能包括 Go message、gRPC stub、validate、Gin handler、grpc-gateway、OpenAPI 和 JSON tag 修补。

必须固定插件版本，否则不同开发机生成内容可能变化。CI 应验证 `make proto` 后 git diff 为空。

## 6. 构建和发布资产

- `scripts/build`：二进制和多阶段镜像；
- `deployments/binary`：裸机服务管理；
- `deployments/docker-compose`：本地服务及依赖；
- `deployments/kubernetes`：Deployment、Service、ConfigMap；
- Jenkinsfile/GitHub workflows：CI/CD 示例。

生成器替换 project/server/image repo/端口/配置。部署模板必须与 server 的 health、metrics、graceful shutdown 行为一致。

## 7. 本仓验证命令

```bash
go test ./pkg/sql2code ./pkg/sql2code/parser ./pkg/replacer
go test ./pkg/app ./pkg/conf
go test -race ./pkg/cache ./pkg/app
git diff --check
```

完整测试可能依赖外部系统。使用受限环境时将 `GOCACHE` 指向可写临时目录。

## 8. 生成项目验收清单

1. 无 `serverNameExample`、`userExample` 等意外残留；
2. 无 `.tpl/.exp/.mgo/.noregistry` 目标文件；
3. 所有 Go 文件 gofmt；
4. import、module path、proto go_package 正确；
5. 基础 CRUD 编译且测试通过；
6. 配置中的密码/DSN 不出现在响应或普通日志；
7. SIGTERM 能完成注销和资源关闭；
8. `/health`、metrics、Swagger/Proto 文档符合环境开关；
9. Docker 镜像使用非 root、固定基础镜像并有最小内容；
10. 重复生成/追加多表不会破坏已有业务代码。
